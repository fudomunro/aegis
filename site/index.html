A private guardian for the agent age

Let agents near your life.
Not into it.

Aegis is a translucent little guardian between your AI agents and the services that hold your music, photos, mail, and calendar. It holds the keys in its tentacles, lets you see everything it touches, and stings anything that reaches too far.

Anatomy of a guardian

Why a jellyfish?

Jellyfish have drifted through the oceans for half a billion years without a brain, a stomach, or a single opinion about your playlists. Aegis is built the same way.

Translucent

You can see right through it. The admin Map shows which agent touched which kind of data, and when. Nothing happens in the murk.

Tentacles hold the keys

Aegis owns every OAuth connection. Tokens stay encrypted on your disk. Agents never see a token and never get asked to log in.

A precise sting

Data grants set an access level per data type — none, freebusy, summary, city, precise, metadata, read, write. Reach too far and the answer is a polite 403. Service limits can only tighten a grant, never widen it.

No stomach

Aegis doesn't store your media. Photos stay in Immich or Google, songs stay on Spotify. It passes things along and keeps nothing for itself.

Our Year, in Songs & Light

An anniversary mixtape that remembers what you were listening to, and what you were looking at.

Ask an agent for your own “Wrapped”, but for the two of you. Aegis pulls liked tracks from Spotify, YouTube Music, and Amazon Music into one list, merged by ISRC so the same song isn't counted three times. Then it lines them up with photo metadata from the same weeks. The agent puts it together. The photos never leave Immich or Google Photos.

  • GET /v1/library/tracks
  • GET /v1/library/photos
  • people[] on photos
  • ISRC-first merge

The player is set to none. The agent can read what you loved, but it can't start blasting music in your kitchen.

The Glass Calendar

A scheduling app can find you an hour. It can't read about your life.

Connect a scheduling app with one click on the Aegis icon. It gets a scoped app token that only sees free/busy: start, end, all-day, status. No titles, attendees, locations, or descriptions. The app knows when you're busy, never why. Flip the toggle off and the token is destroyed.

  • app data grant: events → freebusy
  • GET /v1/library/freebusy
  • Bearer aeg_app_…
  • POST /v1/apps/revoke

Aegis does the redaction itself. Nobody is relying on a prompt asking nicely. Even /v1/library/events comes back with the details blanked.

The Undertow

When you need to know what actually happened, and when, across every inbox you've ever had.

A landlord dispute, an insurance claim, “when did we actually leave?” Aegis keeps a compressed, searchable archive of your mail on your machine and pairs it with your calendar. An agent can rebuild a timeline from receipts, bookings, and cancellations without hammering live Gmail. It can also tell you what the evidence doesn't prove.

  • GET /v1/mail/search
  • GET /v1/library/events
  • local SQLite FTS
  • Takeout import

Search runs against the archive on your own disk. The agent gets a timeline. It never gets your inbox.

How it works

Two currents, one jellyfish

Aegis sits beside Tailscale Aperture, the gateway your agents already talk through. It's a single Go binary on your tailnet.

The hook current

Agent→Aperture→Aegis hook→LLM

Before a prompt reaches the model, Aegis spots the services you mentioned (“my Spotify”, “photos from June”, “my calendar”) and tells the agent where the safe door is: Aegis's own endpoints, with the data grants you set.

The proxy current

Agent→Aegis library→Spotify · Immich · Gmail · …

The agent calls /v1/library/* and gets back plain playlists, tracks, photos, events, and messages, merged across every connected service. Aegis attaches the tokens, caches only successful answers, and enforces every data grant.

Fail-openIf Aegis hits a snag, your request goes through unchanged. Your agent doesn't stall.
Aegis owns OAuthOne encrypted token per connection, refreshed automatically. Agents never see it.
Media stays homeThe original stays with the source service. Aegis only handles metadata.
Tailnet onlyNo public Funnel. Only your own devices and people can reach it.
F.A.Q.

Questions people actually ask

Candid answers, including the ones that don't make Aegis look magical. Product vocabulary lives in the glossary.

Why should I trust Aegis with my data?

You shouldn't. You should audit the code yourself, or at least ask your agent to do it, before you connect Aegis to any sensitive information.

Won't service providers change their APIs and break syncing, making Aegis unstable?

Yes, but we think agentic development can automatically fix that syncing in some really cool ways, at a relatively small cost.

Does Aegis keep copies of my photos, music, or mail?

Not your media. Photos, tracks and documents stay on the service they came from; Aegis fetches them when asked and caches successful reads for a short time. Some data does get stored locally if you choose to: the mail archive (for search), and imports from files you hand it (Takeout, Signal, Quicken, Timeline). All of it lives in one data directory you control.

Do I need Tailscale and Aperture to use it?

Aperture is what lets Aegis step into your LLM requests automatically. Without it, you can still call the library API directly. Tailscale is the security boundary. An API-key mode exists for testing, but Aegis holds keys to your accounts, so we don't recommend running it outside a tailnet, and you should never expose it publicly with Funnel.

Can my agent see my passwords or OAuth tokens?

No. Aegis does the OAuth flow itself and attaches tokens on the server side. Agents never receive them and should never ask you to authorize anything. OAuth tokens and API keys are encrypted on disk under your -token-pass. Admin screens only show whether a credential is present and when it expires.

What can an agent actually see, and how do I limit it?

Only what you allow with data grants, which you set per data type (playlists, contacts, places, …) on the admin page. Sensitive types start off: location history defaults to none, and user-defined types are always opt-in. Per-service limits can only narrow a grant, never widen it. Agent credentials also can't open admin pages, so an agent can't grant itself more access.

Can Aegis change or delete my data?

Almost everything is read-only. Writes are rare and explicit: copying a playlist or liked tracks to another service as a backup, or publishing a photo you pick to Bluesky. Aegis never syncs changes back automatically, and it doesn't delete anything at the source.

What happens when a service (or Aegis) is down?

Aegis fails open. If it can't reach a service or understand a response, your LLM request goes through unchanged and the agent simply gets less help. A broken connector should never block you from talking to your model.

Which services are supported, and can I add my own?

Today: Spotify, YouTube Music, Amazon Music, Google (Photos, Contacts, Calendar, Gmail, Drive), Immich, YNAB, Paperless-ngx, OwnTracks and Bluesky, plus file imports from Google Takeout, Google Timeline, Signal and Quicken. For your own data, a user-defined type (a small JSON schema pack) turns a local file or JSON endpoint into a library type without writing code. New named services are Go connectors, and that's work your agent can help with.

How do I see what my agents have accessed?

The admin Home tab shows which agents touched which data types recently. A local audit log records every access, allowed or denied, without tokens or message bodies, and keeps 30 days by default. Prometheus metrics are available at /metrics.

How do I back up, move, or wipe Aegis?

Everything lives in one data directory (~/Library/Application Support/Aegis on macOS, ~/.local/share/aegis on Linux). Copy it to back up or move. Delete it to wipe. To cut off a service, revoke it from the admin page and also remove Aegis's access in that provider's account settings. Keep -token-pass safe: without it, encrypted credentials can't be recovered and you'll need to reconnect each service.

Surface

Release your own jellyfish

Aegis is open source. Build it, point it at your services, and keep it on your tailnet.

# build
git clone https://github.com/fudomunro/aegis.git && cd aegis
go build -o aegis .

# run it on your tailnet
./aegis -base-url https://aegis.your-tailnet.ts.net \
        -auth-mode tailnet -allowed-logins you@example.com \
        -token-pass "$AEGIS_TOKEN_PASS"
