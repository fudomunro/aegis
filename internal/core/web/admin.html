          Aegis is a synchronous pre_request hook. In Aperture, add a hook named
          aegis whose URL is this instance’s /v1/pre-request,
          and a grant with send_hooks that sends
          user_message and request_body. Use fail-open so chat
          keeps working if Aegis is down. Full operator notes live in

Google Takeout (read-only sync)

      

        
Historical mail export

        
Point Aegis at a Google Takeout export on this machine — an .mbox file, a folder of mbox files, or a Takeout .zip. Treated as a read-only sync location: re-running skips messages already in the archive (by Message-ID) and never writes back to the export.

      

      

        

          
        

        
        
      

      


      
Quicken import (read-only)

      

        
Historical bank exports

        
Import QIF / QFX / OFX exports into the local transaction store so agents can answer money questions that span live YNAB data and older Quicken history. Line-item metadata only — statements and PDFs are never stored. Re-import skips rows already stored (by FITID).

      

      

        

          
        

        
        
      

      

      


      
Signal import (read-only)

      

        
Signal contacts and chats

        
Signal has no public message API. Export on your device, decrypt if needed, then import the result here so agents can answer questions about Signal conversations. Text metadata only — attachments and media are never stored. Re-import skips rows already present.

        
How to produce an export

        
    
          
  • Android: Signal → Settings → Chats → Chat backups → Create backup (remember the passphrase). Decrypt with signalbackup-tools to a plaintext database.sqlite, then import that file.
    • 
          
  • Desktop: copy the Signal data directory’s sql/db.sqlite after decrypting it, or use a community exporter that writes JSONL.
    • 
          
  • JSONL: one JSON object per line with "type":"contact" or "type":"message" (also accepts a {"contacts":[],"messages":[]} bundle).

Why connect Immich to Aegis?

          
Immich is a self-hosted photo/video library (open-source Google Photos on hardware you control) with web/mobile apps and a REST API on port 2283.

          
Once it is the local canonical home for photos, agents can answer “my photos…” via Aegis without your Immich credentials. Aegis holds metadata + proxy URLs only — bytes stay on Immich. Immich can sit beside Google Photos; the same picture merges only on real identity (hash or capture time + size).

          
Prefer cloud-only photos? Skip Immich and use Google Photos. Agent-assisted multi-service setup: #122.

        


        

          
Install Immich (Docker)

          
Official quick start: docs.immich.app. Use our starter .env so compose just works.

          

            

              terminal
              

              
            

            
mkdir -p immich-app && cd immich-app
curl -fsSL -o docker-compose.yml https://github.com/immich-app/immich/releases/latest/download/docker-compose.yml
# save the .env below into this folder as  ./.env   BEFORE the first up
docker compose up -d
docker compose ps   # wait until immich_server is healthy (30–90s)
# then open http://localhost:2283 and register the first account

            

              .env — save as immich-app/.env
              

              
            

            
# Aegis starter Immich .env (issue #121) — first install, no edits required
# File MUST be named .env (not example.env) next to docker-compose.yml

# Photos/videos library directory (relative path is fine; needs free space)
UPLOAD_LOCATION=./library

# Postgres data directory (metadata only; local disk, not a network share)
DB_DATA_LOCATION=./postgres

# Optional timezone — uncomment if your server is not UTC
# TZ=America/Los_Angeles

# Immich release tag
IMMICH_VERSION=v3

# Local database password (letters/digits only). Not your Immich login.
DB_PASSWORD=postgres

# Postgres user / database (defaults are fine for a new install)
DB_USERNAME=postgres
DB_DATABASE_NAME=immich

            
Write .env before the first docker compose up — Postgres only creates DB_DATABASE_NAME on first init.

          

          
Need to send photos later?

          
Skip ahead — connect to Aegis first. Next step covers seeding the library.

          
Troubleshooting

          
    
            
  • variable is not set / empty section between colons → .env missing or still named example.env.
    • 
            
  • ERR_CONNECTION_REFUSED on :2283 → docker compose ps (want immich_server healthy + port map); logs often show database "immich" does not exist if Postgres inited without the name — CREATE DATABASE immich; or wipe ./postgres and re-up.
    •
